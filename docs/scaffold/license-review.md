# Runtime component evidence

We examined the 89 non-main runtime components in the Linux/amd64 module graph
generated by cyclonedx-gomod v1.12.0. The complete BOM and dependency graph remain
in `bom.cdx.json`.

The 85 third-party components require detected SPDX evidence. The four exact
first-party ANI modules in `first-party-modules.json` have **undeclared licenses**;
their BOM license evidence remains absent (no license assertion). They are not
classified as MIT, Apache, or a fabricated LicenseRef. The frozen upstream layout
notice is not a license grant for these services.

For those four modules, `make supply-chain-verify` checks the exact `go.mod` pin,
both `go.sum` entries, the published download checksums, its VCS URL/subdirectory
and full `Origin.Hash`, and the BOM's identity and checksum. A different module,
version, source or checksum cannot inherit this classification. This corrects
the gate's treatment of first-party provenance as third-party licensing; it does
not grant a license or assert that every non-main component has SPDX evidence.

`make audit` retains vulnerability scanning, full-history secret scanning,
deterministic SBOM generation, the frozen notice check, strict third-party
license evidence, and synchronization of these component counts.
